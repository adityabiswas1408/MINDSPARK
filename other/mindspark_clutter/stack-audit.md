## 6. Stack Recommendation

### 6.1 Recommended Stack — Layer by Layer

1. **Frontend Framework**: **Next.js (App Router)**
   - *Runner-up*: React SPA (Vite)
   - *Solves*: Excellent routing for distinct role areas, seamless server integrations for secure grading, and built-in image optimization.
   - *Gaps*: Slightly more complex offline PWA setup compared to a raw Vite SPA.

2. **UI Component Library**: **shadcn/ui + Radix Primitives**
   - *Runner-up*: Mantine
   - *Solves*: Highly accessible, customizable components out-of-the-box, saving time on admin dashboards.
   - *Gaps*: Requires manual styling maintenance.

3. **Styling System**: **Tailwind CSS**
   - *Runner-up*: CSS Modules
   - *Solves*: Rapid UI iteration and built-in dark mode support.
   - *Gaps*: Can clutter JSX.

4. **State Management**: **Zustand (Client) + React Query (Server Cache)**
   - *Runner-up*: Redux Toolkit
   - *Solves*: Lightweight state for exam timers and complex UI states without boilerplate.
   - *Gaps*: React Query needs careful configuration for offline-first syncing.

5. **Offline Data Sync**: **Dexie.js (IndexedDB)**
   - *Runner-up*: WatermelonDB
   - *Solves*: Local storage for offline exam submissions before syncing back to the server.
   - *Gaps*: Requires custom sync conflict resolution logic.

6. **Backend / API Layer**: **Next.js Server Actions & API Routes**
   - *Runner-up*: Separate Node.js/Express Server
   - *Solves*: Co-located backend logic for fast iteration, native type-safety.
   - *Gaps*: Long-running tasks (>15s) may timeout on serverless platforms.

7. **Database**: **PostgreSQL**
   - *Runner-up*: MySQL
   - *Solves*: ACID compliance for exam grading, deep relational modeling for cohorts, and Row-Level Security (RLS) for multi-tenancy.
   - *Gaps*: Connection pooling overhead in serverless (needs PgBouncer/Supabase).

8. **ORM / Query Layer**: **Drizzle ORM**
   - *Runner-up*: Prisma
   - *Solves*: Edge-compatible, highly performant, type-safe SQL wrapper.
   - *Gaps*: Migration management is slightly more manual than Prisma.

9. **Auth System**: **Supabase Auth**
   - *Runner-up*: Clerk
   - *Solves*: Ties directly into PostgreSQL RLS for secure, database-level authorization.
   - *Gaps*: Less out-of-the-box UI compared to Clerk.

10. **Real-time Layer**: **Supabase Realtime (WebSockets)**
    - *Runner-up*: Socket.io
    - *Solves*: Broadcasts lobby state and live exam monitoring effortlessly over existing DB infrastructure.
    - *Gaps*: Subject to connection limits based on pricing tiers.

11. **Email / Notifications**: **Resend**
    - *Runner-up*: SendGrid
    - *Solves*: Modern developer experience, React Email support for transactionals.
    - *Gaps*: Purely email, requires secondary provider for SMS/Push.

12. **Hosting / Deployment**: **Vercel**
    - *Runner-up*: AWS Amplify
    - *Solves*: Zero-config Next.js deployments, edge network distribution.
    - *Gaps*: Serverless cold starts could occasionally delay API routes.

### 6.3 Why Not the Obvious Alternatives
- **Why not a pure SPA (React/Vite + Express backend)?**
  While an SPA is great for offline apps, Next.js provides superior file-system routing for the complex admin/student divide, and Server Actions dramatically speed up building secure endpoints for grading without needing a distinct backend codebase.
- **Why not MongoDB / NoSQL?**
  The domain is highly relational (institutions -> cohorts -> students -> submissions). PostgreSQL guarantees data integrity and allows for complex analytical queries on grade boundaries that NoSQL would struggle with.
- **Why not Firebase?**
  While Firebase handles real-time well, PostgreSQL's relational power and Supabase's open-source nature offer better long-term flexibility and analytical capabilities for complex edtech data.
