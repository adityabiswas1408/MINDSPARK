Student Profile mockup — 3 frames

Single read-only profile card with a minimal hero (avatar + name + role line). School Info section visible by default. More Info section collapses/expands as one block. NULL fields render as Not mentioned. Avatar falls back to initials when avatar_url is null. No editable fields, no save flows. Standard student shell with Profile active in the sidebar (Help & Support nav entry removed).

Frame 1 — /student/profile · default state (More info collapsed)

Hero strip + School Info section visible. More Info collapsed to a single toggle row showing the chevron pointing down. This is the landing state.

Frame 3 — /student/profile · Null-heavy state (More Info expanded with mostly empty fields)

Same card with the More Info section showing several Not mentioned fallbacks. This is what a student record looks like when only the minimum required fields (full_name + level + cohort) were entered at admin-create time. Demonstrates the fallback styling: italic + lighter colour for unfilled fields. The verified pill is absent because consent is unverified — the row shows "Not verified" instead.
